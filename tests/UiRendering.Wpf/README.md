# Native WPF offscreen component renders

These PNGs are generated by compiled production MainWindow/SettingsWindow XAML, App resources and one shared AppViewModel through WPF RenderTargetBitmap. They are NOT desktop screenshots. No window was shown and no desktop input automation, game, unlocker or installer was executed.

The default main/settings images have empty game paths and 240 FPS. Their environment fields come from an actual AppViewModel.RefreshAsync on this machine: NVAPI and the Windows registry, not fixture hardware values. settings-long-path-fixture is a separately named test image with explicitly fake paths.

The test detaches the production App Startup handler before any bounded dispatcher flush, preventing normal startup from showing a window. It paints the real Window.Background plus real content. No shown-window Loaded interaction is claimed.

100%, 150%, 200% indicate RenderTargetBitmap output at 96, 144 and 192 DPI. They do not mean the desktop monitor DPI was changed. Actual desktop interaction, per-monitor scaling and settings-instance activation remain separate validation items after desktop unlock.

Source: tests/UiRendering.Wpf. Actual result: 15 passed, 0 failed; offscreen-results.log contains dimensions and actual environment values. The test identified and fixed duplicate Padding in the real TextBox template: text viewport increased from 6 to 22 DIPs with no font/artwork/layout redesign.
