# Native cursor ownership

`native_cursor.hpp` keeps the Windows cursor independent of the game's base render rate while a ReShade menu is open. It does not raise the menu's render rate. `Update(HWND, wanted, Shape, menuOpen)` is called from the overlay callback; only a confirmed visible native cursor permits suppressing that frame's ImGui cursor. No ImGui IO memory is written across ABI versions. A temporary `ImGuiMouseCursor_None` request is separate from closing the menu.

A one-shot target-thread message hook installs a window subclass on the window's owner thread. The subclass handles client `WM_SETCURSOR` and the restoration watchdog. `cursor_hooks.hpp` installs `SetCursor`, `GetCursor`, and `ShowCursor` together in a process-local Detours transaction using bounded thread enrollment. Installation is attempted once; failure leaves the APIs unchanged and requires restarting the process before another attempt. No driver, system-wide hook, ReShade binary, input position, clipping, or global cursor resource is changed.

Only the owner thread with an active menu lease, a fresh heartbeat, the target foreground window, and a pointer inside its client area participates. Other threads and inactive sessions pass through unchanged. State is thread-local; hook callbacks do not acquire the adapter mutex. The adapter itself calls original trampolines with a recursion guard.

During a lease, game `SetCursor` calls update the game's latest requested handle (including null) and return its previous requested handle. `GetCursor` returns that same game view. Game `ShowCursor` calls update a separate logical count and return the exact new count, while the physical cursor remains visible. Closing, focus loss, leaving the client, destruction, or timeout restores the latest game cursor and reconciles its cumulative count. The watchdog never periodically reclaims a cursor from another writer; it sets a cursor only on acquisition or intentional shape change.

Visibility acquisition makes at most eight increments and restores all of them if it fails. The logical-to-physical count difference is limited to 128. A request exceeding this limit first restores the existing bounded difference, then passes the request through and stops management for the session. Unexpected visibility changes outside the managed APIs and a stalled overlay heartbeat also stop management safely. These are exceptional safety boundaries, not a normal per-frame switch between hardware and software cursors. Status transitions are logged from the overlay callback, outside hooks and locks.

Callbacks and trampolines are pinned until process exit, with no hot detach. `Stop()` requests owner-thread restoration; never call it from `DllMain`. A blocked owner message thread cannot restore until it resumes. Cross-thread attached input queues, direct native system calls bypassing these public APIs, or other cursor hooks may be incompatible; they are not claimed to be virtualized. In-game behavior still requires validation.

Run `Test-NativeCursor.ps1 -DependencyDirectory <prepared renodx-build directory>`. Tests cover bounded count reconciliation, exact previous-handle semantics, other-thread passthrough, atomic installation failure, actual Detours on inert local functions, and public Update/subclass/watchdog integration through a hidden window. Cursor and foreground observations are injected for active-mode tests; the user's mouse and actual display counter are not changed.

Win32 semantics: [ShowCursor](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showcursor), [SetCursor](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setcursor).
