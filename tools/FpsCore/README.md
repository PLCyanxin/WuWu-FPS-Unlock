# 内置帧率解锁模块

本模块由 `30launchers/WutheringWaves-FPS-unlocker` 的 FPS 部分派生，上游提交和原始二进制来源见 `SOURCE.json`，许可证为 MIT。当前随包二进制及源码摘要由 `components/PROVENANCE.json` 记录。

## 定位与维持

模块仅在 `Client-Win64-Shipping.exe` 中初始化，保留上游 154 字节特征与候选顺序：按地址升序选取首个特征，在其后查找 `0x70`，向前 4 KiB 查找本轮第二个不同的 FPS 浮点候选。每轮重新计数，避免同一个地址在多轮搜索中被重复认领。后续 `0x70` 查找限制在特征所在的同一 `VirtualQuery` 区域内，最多读取 64 KiB；合法 `0xFF` 是普通数据。候选尚未就绪时每 51ms 重试，最多等待 915 秒。

接收到合法目标指令前不写入。正常维持每 51ms 检查一次，仅在当前值与目标不同的时候写入；成功写入后回读，确认一致才更新 `applied`。暂时读取失败、当前值无效或写入失败时暂停写入，改为每 250ms 检查原地址。恢复前必须通过原映射和原特征锚点校验，当前值也须为有限的 30–420 浮点数。零值与其他异常值不会被改写。

映射或锚点发生变化时停止维护，并保留诊断状态。运行中不会重新扫描、选择另一浮点地址，也不会重新加载模块。定位文本及数值规则仍是上游启发式方法，不能视为对任意游戏版本布局的证明。64 KiB 是保守的工作量限制，超出时报告第二标记不可用。映射比较覆盖区域起点、长度、AllocationBase、Type 与 AllocationProtect；Windows 不提供此处可用的分配世代标识，无法绝对排除两次检查间同址同布局复用。

## 生命周期与通信

模块使用一个维持线程和一个可取消的管道线程。扫描或维护停止后，管道继续提供状态；显式停止请求或游戏退出才结束线程。成功初始化会固定模块，不能热卸载；`DllMain` 不等待线程。`RequestFpsCoreStop` 仅用于发出停止请求，启动器不调用它。

原管道名称及六字段 FPS 指令保持不变。指令长度上限为 128 字节，必须完整且目标为 30–420 的整数；拒绝尾随内容、溢出、非数值与超长消息。其他五个字段不控制功能。六字段指令没有回复。

启动器可发送精确 ASCII 消息 `status-v1`，读取一条最长 128 字节、以换行结束的消息：

```text
WUWA-FPS/1,pid,state,reason,target,applied,repairs\n
```

除版本前缀外，字段均为十进制整数。`target` 是最近接受的目标，初始为 0；`applied` 是最后确认维持的目标值，初始为 0；`repairs` 只统计成功执行的写入。暂停或停止后的 `applied` 是历史值，必须结合 `state` 与 `reason` 判断当前状态。内存回读、管道连接及指令接收均不能证明实际渲染帧率。

状态码：0 等待渲染窗口、1 查找定位标记、2 查找候选、3 等待指令、4 正在维持、5 暂停、6 停止。

原因码：0 无、1 无定位标记、2 第二标记不可用、3 候选不可读、4 候选超时、5 目标不可读、6 目标值无效、7 写入或回读失败、8 目标映射变化、9 渲染窗口超时、10 停止请求、11 锚点变化、12 内部错误。

管道采用可取消重叠 I/O，拒绝远程客户端，不使用 `FlushFileBuffers` 等待客户端读取。保留 Windows 默认 DACL；本协议不是本地客户端身份认证机制。启动器须核对管道服务器 PID 与本次游戏身份。状态按需查询，不在维持循环中写磁盘日志。

## 构建与隔离验证

```powershell
./tools/FpsCore/Build.ps1 -OutputDirectory ./artifacts/tests/fps-core
```

需 Windows x64 MSVC 工具链。脚本生成 `ww_fps_core_candidate.dll` 并运行隔离测试，不复制到安装或游戏目录。测试使用自有内存与私有管道，执行生产维护编排、映射校验、协议和取消路径；不执行生产全进程扫描、不访问游戏进程。隔离验证与游戏实测是不同验证层级，算法基准不能视为游戏 FPS 收益。
